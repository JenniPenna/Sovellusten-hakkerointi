# h5 Binääri tässä, missä koodit?

## Lab 0

### 1. Ohjelman tarkastelu

Alkuperäinen ohjelma oli:

```c
#include <stdio.h>

void buggy_function(int *arr, int size) {
    for (int i = 0; i <= size; i++) {
        printf("Element %d: %d\n", i, arr[i]);
    }
}

int main() {
    int numbers[] = {1, 2, 3, 4, 5};
    buggy_function(numbers, 5);
    return 0;
}
```

Koska C-kielessä taulukon indeksit alkavat nollasta, taulukon indeksit ovat 0-4. Suurin sallittu indeksi on siis 4.

Huomasin, että `for`-silmukan ehtona on:

```c
i <= size
```

Ohjelmassa `size` saa arvon 5:

```c
buggy_function(numbers, 5);
```

Tämän vuoksi silmukka suoritetaan myös silloin, kun `i` on 5. Tällöin ohjelma yrittää lukea taulukon ulkopuolelta:

```c
arr[5]
```

## 2. Ohjelman kääntäminen

Ensin käänsin ohjelman GCC-kääntäjällä debuggeria varten.

Komento:

```bash
gcc -g buggy_program.c -o buggy_program
```

Tämän jälkeen ohjelman voi suorittaa komennolla:

```bash
./buggy_program
```

## 3. GNU Debuggerin käynnistäminen

Käynnistin GNU Debuggerin seuraavalla komennolla:

```bash
gdb ./buggy_program
```

Kun GDB käynnistyi, asetin breakpointin `buggy_function`-funktioon:

```text
break buggy_function
```

Tämän jälkeen käynnistin ohjelman:

```text
run
```

Debugger pysähtyi `buggy_function`-funktion alkuun breakpointin kohdalle.

---

## 4. Ohjelman tutkiminen debuggerilla

Halusin tutkia ohjelmaa vaihe vaiheelta.

Käytin komentoa:

```text
next
```

`next` suorittaa ohjelman seuraavan rivin ja pysäyttää ohjelman uudelleen.

Toistin `next`-komentoa, jotta pystyin seuraamaan `for`-silmukan etenemistä.

Muuttujan arvo voidaan tarkistaa GDB:ssä komennolla:

```text
print i
```

Tarkistin myös `size`-muuttujan arvon:

```text
print size
```

Debugger näytti, että:

```text
i = 5
size = 5
```

Tässä vaiheessa huomasin virheen.

Silmukan ehto oli:

```c
i <= size
```

Koska:

```text
i = 5
size = 5
```

ehto `i <= size` on edelleen tosi.

Ohjelma suorittaa siis vielä yhden kierroksen ja yrittää käyttää:

```c
arr[5]
```
---

## 5. Virheen analysointi

Taulukko on:

```c
int numbers[] = {1, 2, 3, 4, 5};
```

Taulukon sisältö ja indeksit ovat:

```text
Indeksi:  0  1  2  3  4
Arvo:     1  2  3  4  5
```

Indeksi 5 ei ole olemassa.

Virhe johtuu siis siitä, että `for`-silmukka menee yhden kierroksen liian pitkälle.

---

## 6. Virheen korjaaminen

Korjasin `for`-silmukan ehdon.

Alkuperäinen rivi oli:

```c
for (int i = 0; i <= size; i++) {
```

Muutin sen muotoon:

```c
for (int i = 0; i < size; i++) {
```

Korjattu funktio on:

```c
void buggy_function(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        printf("Element %d: %d\n", i, arr[i]);
    }
}
```

Nyt silmukka suoritetaan arvoilla:

```text
i = 0
i = 1
i = 2
i = 3
i = 4
```

Kun `i` saavuttaa arvon 5, ehto:

```text
i < size
```

ei enää ole tosi.

Tämän vuoksi ohjelma ei enää yritä käyttää `arr[5]`.

---

## 7. Ohjelman kääntäminen uudelleen

Korjauksen jälkeen käänsin ohjelman uudelleen:

```bash
gcc -g buggy_program.c -o buggy_program
```

Tämän jälkeen suoritin ohjelman:

```bash
./buggy_program
```

Ohjelma tulosti:

```text
Element 0: 1
Element 1: 2
Element 2: 3
Element 3: 4
Element 4: 5
```

Nyt ohjelma käsittelee kaikki viisi taulukon alkiota eikä yritä käyttää taulukon ulkopuolista indeksiä.

# Lab2

## Ohjelman käynnistäminen

Lab2-kansiossa oli `passtr`-hakemisto. Hakemiston sisällä oli muun muassa seuraavat tiedostot:

```text
Makefile
passtr
passtr2o
passtr.c
README.md
```

README:n mukaan `passtr2o` oli valmiiksi käännetty binääri, jota tehtävässä piti tutkia debuggerilla.

Käynnistin ohjelman komennolla:

```bash
./passtr2o
```
Ohjelma käynnistyi ja kysyi:

```text
What's the password?
```

## GDB:n käynnistäminen

Käynnistin GNU Debuggerin komennolla:

```bash
gdb ./passtr2o
```

Ensimmäiseksi tarkistin ohjelman funktiot komennolla:

```gdb
info functions
```

GDB näytti muun muassa seuraavat funktiot:

```text
main
EaseEAs
check_password
mAsdf3a
```

Koska `check_password` vaikutti nimen perusteella salasanan tarkistamiseen liittyvältä, tutkin sitä ensin.

## check_password-funktion tutkiminen

Käytin komentoa:

```gdb
disassemble check_password
```

Tuloksena oli:

```asm
0x0000000000001257 <+0>:	xor    %eax,%eax
0x0000000000001259 <+2>:	ret
```

Funktio ei kuitenkaan tehnyt varsinaista salasanan tarkistusta, vaan palautti vain arvon 0. Tämän vuoksi tutkin seuraavaksi `main`-funktiota.

## main-funktion tutkiminen

Käytin komentoa:

```gdb
disassemble main
```

`main`-funktion assemblysta löytyi kohta, jossa ohjelma lukee käyttäjän syötteen:

```asm
call   0x1060 <__isoc99_scanf@plt>
```

Sen jälkeen kutsutaan funktiota:

```asm
call   0x125a <mAsdf3a>
```

Tämä vaikutti kiinnostavalta, koska `mAsdf3a` sai käyttäjän syötteen käsiteltäväkseen.

`main`-funktiossa oli myös kutsu:

```asm
call   0x1219 <EaseEAs>
```

Tämä funktio suoritetaan salasanan tarkistuksen jälkeen, joten se saattaisi liittyä FLAGin tulostamiseen.

## mAsdf3a-funktion tutkiminen

Seuraavaksi tutkin `mAsdf3a`-funktion:

```gdb
disassemble mAsdf3a
```

Funktiossa oli muun muassa seuraavat käskyt:

```asm
mov    %rdi,%rbp
mov    %rsi,%rbx
```

sekä:

```asm
movsbl 0x0(%rbp,%rax,1),%edx
movsbl (%rbx,%rax,1),%ecx
```

Tämän perusteella funktio käsittelee merkkijonoja merkki kerrallaan.

Kiinnostavin osa oli:

```asm
test   $0x1,%al
je     0x1299
sub    $0x7,%edx
jmp    0x129c
add    $0x3,%edx
cmp    %ecx,%edx
jne    0x12ac
```

Tästä pystyin päättelemään, että funktio muuttaa vertailtavan merkkijonon merkkejä indeksin perusteella ja vertaa tulosta käyttäjän antamaan salasanaan.

## Funktioparametrien selvittäminen

Asetin breakpointin `mAsdf3a`-funktioon:

```gdb
break mAsdf3a
```

Käynnistin ohjelman:

```gdb
run
```

Ohjelma kysyi salasanaa, joten annoin testiksi:

```text
hello
```

GDB pysähtyi `mAsdf3a`-funktion alkuun.

Tutkin rekistereitä komennolla:

```gdb
info registers rdi rsi rax
```

Tämän jälkeen tutkin, mitä merkkijonoja rekisterit osoittivat:

```gdb
x/s $rdi
```

Tulokseksi sain:

```text
0x7fffffffdce1: "anLTj4u8"
```

Seuraavaksi:

```gdb
x/s $rsi
```

Tulokseksi sain:

```text
0x7fffffffdcfc: "hello"
```

Tästä selvisi, että:

```text
rdi = "anLTj4u8"
rsi = käyttäjän antama salasana
```

Eli ohjelma vertasi käyttäjän syötettä merkkijonoon `anLTj4u8` tehdyn muunnoksen perusteella.

## Salasanan selvittäminen

Assemblysta selvisi, että ohjelma käsittelee merkkijonon merkkejä yksi kerrallaan.

Parillisilla indekseillä merkkiin lisätään 3:

```text
+3
```

Parittomilla indekseillä merkistä vähennetään 7:

```text
-7
```

Merkkijono oli:

```text
anLTj4u8
```

Kun muunnos tehdään:

```text
a + 3 = d
n - 7 = g
L + 3 = O
T - 7 = M
j + 3 = m
4 - 7 = -
u + 3 = x
8 - 7 = 1
```

Saadaan salasana:

```text
dgOMm-x1
```

## Salasanan testaaminen

Testasin löytynyttä salasanaa käynnistämällä ohjelman uudelleen:

```gdb
run
```

Kun ohjelma kysyi:

```text
What's the password?
```

annoin:

```text
dgOMm-x1
```

Asetin ohjelman pysähtymään `mAsdf3a`-funktioon ja tarkistin palautusarvon komennolla:

```gdb
info registers rax
```

GDB näytti:

```text
rax            0x1                 1
```

Tämä tarkoitti, että salasanan tarkistus onnistui, koska `mAsdf3a` palautti arvon `1`.

## FLAGin löytäminen

Jatkoin ohjelman suorittamista komennolla:

```gdb
continue
```

Tällä kertaa ohjelma hyväksyi salasanan ja tulosti:

```text
Yes! That's the password. FLAG{Lari-rsvRDx04WMBZpuwg4qfYwzdcvVa0oym}
```

Näin sain selville tehtävän vaatiman FLAGin.

## Lopputulos

Ohjelman oikea salasana oli:

```text
dgOMm-x1
```

Ohjelman tulostama FLAG oli:

```text
FLAG{Lari-rsvRDx04WMBZpuwg4qfYwzdcvVa0oym}
```

## Mitä uutta opin GNU Debuggerista

Opin Lab2-tehtävässä erityisesti seuraavia asioita:

* `info functions` -komennolla voidaan nähdä ohjelman funktioita.
* `disassemble`-komennolla voidaan tutkia funktion assembly-koodia.
* `continue` jatkaa ohjelman suorittamista seuraavaan breakpointiin tai ohjelman loppuun.
* `info registers` -komennolla voidaan tarkastella CPU-rekisterien arvoja.
* `x/s`-komennolla voidaan tarkastella muistiosoitteessa olevaa merkkijonoa.
* Funktioiden parametreja voidaan tutkia rekisterien avulla.
* Assembly-koodista voidaan päätellä, miten ohjelma käsittelee ja vertaa tietoa.
* Ohjelman salasanaa ei aina tarvitse arvata, vaan sen tarkistuslogiikkaa voidaan analysoida debuggerilla.
* GDB:tä voidaan käyttää myös ohjelman toiminnan tutkimiseen silloin, kun alkuperäistä lähdekoodia ei ole käytettävissä.

## Mitä en vielä oppinut tai mikä jäi epäselväksi

En vielä hallitse assembly-koodin lukemista täysin itsenäisesti. Esimerkiksi rekisterien, muistiosoitteiden ja hyppykäskyjen (`jne`, `je`, `jmp`) merkitysten ymmärtäminen vaati vielä paljon tulkintaa.

Myös GDB:n rekisterien ja muistiosoitteiden käyttö on vielä osittain epäselvää. Osaan käyttää esimerkiksi `info registers`- ja `x/s`-komentoja, mutta en vielä täysin ymmärrä kaikkia rekistereitä tai sitä, miten ohjelman muistialueet toimivat.

Tehtävä opetti kuitenkin hyvin, miten debuggeria voidaan käyttää järjestelmällisesti ohjelman toiminnan selvittämiseen.
