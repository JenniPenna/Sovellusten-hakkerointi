# Tapo C200 -kameran tietoturvatutkimus

Tein tämän H6-tehtävän tutkimalla TP-Link Tapo C200 -kameran
ohjelmistoa. Tarkoitus oli selvittää mitä kamera pitää sisällään ja onko siinä tietoturva-aukkoja,
sekä yrittää saada selville laitteen root-salasana.

## Mitä tein

### Firmwaren purkaminen

Aloitin tutkimalla saamaani dump-tiedostoa. Käytin binwalkia, joka
osaa löytää tiedoston sisältä erilaisia tiedostojärjestelmiä ja purkaa
ne:

```
binwalk dump-tapo-c200v3-1.4.2.bin
binwalk -e dump-tapo-c200v3-1.4.2.bin
```

Tämä löysi kamerasta muun muassa Linux-kernelin ja SquashFS-nimisen
tiedostojärjestelmän, joka purkautui automaattisesti omaksi
kansiokseen. Sieltä löytyi kameran koko käyttöjärjestelmä: kansiot
kuten `/bin`, `/etc` ja `/lib`, ja niissä kameran ohjelmat.

Latasin myös firmware-paketin (tehtävänannossa annetulla AWS-komennolla) ja purin sen erillisellä
`tp-link-decrypt`-työkalulla (https://github.com/robbins/tp-link-decrypt),
joka osaa purkaa TP-Linkin salaaman firmware-paketin.

```
git clone https://github.com/robbins/tp-link-decrypt
cd tp-link-decrypt
./preinstall.sh
./extract_keys.sh
make
./bin/tp-link-decrypt ../Tapo_C200v4_en_1.4.2.bin
```

Tämä onnistui ja tuotti puretun firmware-tiedoston. Vertailin sen
sisältöä (`diff -rq`) kamerasta otettuun dumppiin ja huomasin, että
niiden sisältämät tiedostot olivat tutkimuksessani yhteneviä — eli
kamerassa pyörii sama ohjelmisto kuin mitä TP-Link virallisesti jakaa.

### Sovellusten etsiminen

Puretusta tiedostojärjestelmästä löysin `bin`-kansiosta muutaman
ohjelman, joista tärkein oli `main` — se on käytännössä koko kameran
"aivot", joka hoitaa kaikki toiminnot (verkko, video, asetukset,
kirjautuminen).

```
file bin/main
ls -la bin/
```

`main` on MIPS-prosessorille käännetty ohjelma.

### Ohjelman suojausten tarkistus

Tarkistin `checksec`-työkalulla, onko `main`-ohjelmassa käytössä
nykyaikaisia suojauksia jotka vaikeuttaisivat sen hyväksikäyttöä:

```
checksec --file=./bin/main
```

Tulos oli huono: kaikki neljä tärkeintä suojausta (RELRO, Stack
Canary, NX, PIE) puuttuivat kokonaan. Tämä tarkoittaa, että jos
ohjelmasta löytyisi bugi, sen hyödyntäminen olisi paljon helpompaa
kuin nykyaikaisessa ohjelmassa.

### Tekstien etsiminen ohjelmasta

Katsoin `strings`-komennolla mitä tekstejä ohjelman sisältä löytyy:

```
strings bin/main | grep -i "passwd\|password"
strings bin/main | grep -E "strcpy|sprintf|system|popen"
```

Tästä löytyi paljon salasanoihin liittyviä funktioita, esimerkiksi
`gen_root_passwd`, `get_cam_passwd`, `factory_passwd` ja merkkijono
`Hash(password) = %s`. Tämä osoittaa, että ohjelmassa käytetään
ainakin yhdessä kohdassa salasanojen hashaukseen liittyvää käsittelyä,
ja että kamera tekee jonkinlaisen avaintenvaihdon TP-Linkin pilven
kanssa (`deviceSecret`).

### Vaarallinen kohta koodissa

Tässä vaiheessa avasin `main`-binäärin Ghidra-nimisellä
takaisinmallinnustyökalulla (se muuttaa konekoodin luettavaan
muotoon). Etsin sieltä funktiota `onboarding_execute_shell_cmd` ja
löysin tämän:

```c
__stream = popen(param_1,"r");
```

Tämä funktio suorittaa annetun tekstin suoraan komentona
tarkistamatta mitään. Jäljitin mistä tätä funktiota kutsutaan ja
löysin yhden kutsun, jossa komento oli kovakoodattu
(`"ifconfig wlan1 | grep addr:"`) tämä yksi kutsu ei siis ole
vaarallinen. Kahta muuta kutsupaikkaa en ehtinyt jäljittää täysin
loppuun, joten en voi olla varma onko haavoittuvuus oikeasti
hyödynnettävissä. Itse funktion olemassaolo tällä tavalla toteutettuna
on kuitenkin huono merkki.

### Root-salasanan etsiminen

Yritin ensin löytää salasanan tavalliseen tapaan:

```
find rootfs -iname "passwd*" -o -iname "shadow*"
```

Näitä tiedostoja ei löytynyt lainkaan.

Sitten kokeilin leikata suoraan irti pari kohtaa kameran flash-muistin
raakadatasta, koska tiesin blogikirjoituksesta mistä kohdasta
asetukset yleensä löytyvät:

```
dd if=dump-tapo-c200v3-1.4.2.bin of=config_partition.bin bs=1 skip=$((0x40000)) count=$((0x50000-0x40000))
dd if=dump-tapo-c200v3-1.4.2.bin of=user_record_partition.bin bs=1 skip=$((0x770000)) count=$((0x7f0000-0x770000))
file config_partition.bin user_record_partition.bin
```

`user_record`-osio oli täysin tyhjä. `config`-osio sen sijaan sisälsi
dataa, joka alkoi tekstillä `NVMP-CONFIG`, mutta loppu data näytti
täysin satunnaiselta eli se on salattu. En ehtinyt selvittää millä
avaimella tai algoritmilla tämä konfiguraatio on salattu, joten en
päässyt itse salasanaan käsiksi.

## Hyödynnettävyyden arviointi

Tutkimuksessa löytyi useita mahdollisesti turvallisuuteen vaikuttavia
asioita, mutta kaikkien niiden käytännön hyödyntämistä ei pystytty
varmistamaan. `main`-ohjelman puuttuvat suojausmekanismit voivat
helpottaa mahdollisen muistinkäsittelyhaavoittuvuuden hyödyntämistä.
Lisäksi käyttöjärjestelmäkomentoja suorittava funktio on mahdollinen
riskikohta, mutta en pystynyt osoittamaan, että siihen voitaisiin
syöttää hyökkääjän omaa komentoa ulkopuolelta.
