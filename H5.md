## Lab 0 – GNU Debuggerin harjoittelu

### 1. Ohjelman tarkastelu

Alkuperäinen ohjelma oli:

```c
#include <stdio.h>

void buggy_function(int *arr, int size) {
    for (int i = 0; i <= size; i++) {
        printf("Element %d: %d\n", i, arr[i]);
    }
}

int main() {
    int numbers[] = {1, 2, 3, 4, 5};
    buggy_function(numbers, 5);
    return 0;
}
```

Koska C-kielessä taulukon indeksit alkavat nollasta, taulukon indeksit ovat 0-4. Suurin sallittu indeksi on siis 4.

Huomasin, että `for`-silmukan ehtona on:

```c
i <= size
```

Ohjelmassa `size` saa arvon 5:

```c
buggy_function(numbers, 5);
```

Tämän vuoksi silmukka suoritetaan myös silloin, kun `i` on 5. Tällöin ohjelma yrittää lukea taulukon ulkopuolelta:

```c
arr[5]
```

## 2. Ohjelman kääntäminen

Ensin käänsin ohjelman GCC-kääntäjällä debuggeria varten.

Komento:

```bash
gcc -g buggy_program.c -o buggy_program
```

Tämän jälkeen ohjelman voi suorittaa komennolla:

```bash
./buggy_program
```

## 3. GNU Debuggerin käynnistäminen

Käynnistin GNU Debuggerin seuraavalla komennolla:

```bash
gdb ./buggy_program
```

Kun GDB käynnistyi, asetin breakpointin `buggy_function`-funktioon:

```text
break buggy_function
```

Tämän jälkeen käynnistin ohjelman:

```text
run
```

Debugger pysähtyi `buggy_function`-funktion alkuun breakpointin kohdalle.

## 4. Ohjelman tutkiminen debuggerilla

Halusin tutkia ohjelmaa vaihe vaiheelta.

Käytin komentoa:

```text
next
```

`next` suorittaa ohjelman seuraavan rivin ja pysäyttää ohjelman uudelleen.

Toistin `next`-komentoa, jotta pystyin seuraamaan `for`-silmukan etenemistä.

Muuttujan arvo voidaan tarkistaa GDB:ssä komennolla:

```text
print i
```

Tarkistin myös `size`-muuttujan arvon:

```text
print size
```

Debugger näytti, että:

```text
i = 5
size = 5
```

Tässä vaiheessa huomasin virheen.

Silmukan ehto oli:

```c
i <= size
```

Koska:

```text
i = 5
size = 5
```

ehto `i <= size` on edelleen tosi.

Ohjelma suorittaa siis vielä yhden kierroksen ja yrittää käyttää:

```c
arr[5]
```
---

## 5. Virheen analysointi

Taulukko on:

```c
int numbers[] = {1, 2, 3, 4, 5};
```

Taulukon sisältö ja indeksit ovat:

```text
Indeksi:  0  1  2  3  4
Arvo:     1  2  3  4  5
```

Indeksi 5 ei ole olemassa.

Virhe johtuu siis siitä, että `for`-silmukka menee yhden kierroksen liian pitkälle.

---

## 6. Virheen korjaaminen

Korjasin `for`-silmukan ehdon.

Alkuperäinen rivi oli:

```c
for (int i = 0; i <= size; i++) {
```

Muutin sen muotoon:

```c
for (int i = 0; i < size; i++) {
```

Korjattu funktio on:

```c
void buggy_function(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        printf("Element %d: %d\n", i, arr[i]);
    }
}
```

Nyt silmukka suoritetaan arvoilla:

```text
i = 0
i = 1
i = 2
i = 3
i = 4
```

Kun `i` saavuttaa arvon 5, ehto:

```text
i < size
```

ei enää ole tosi.

Tämän vuoksi ohjelma ei enää yritä käyttää `arr[5]`.

## 7. Ohjelman kääntäminen uudelleen

Korjauksen jälkeen käänsin ohjelman uudelleen:

```bash
gcc -g buggy_program.c -o buggy_program
```

Tämän jälkeen suoritin ohjelman:

```bash
./buggy_program
```

Ohjelma tulosti:

```text
Element 0: 1
Element 1: 2
Element 2: 3
Element 3: 4
Element 4: 5
```

Nyt ohjelma käsittelee kaikki viisi taulukon alkiota eikä yritä käyttää taulukon ulkopuolista indeksiä.
