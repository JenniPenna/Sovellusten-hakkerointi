# Lab2

## Ohjelman käynnistäminen

Lab2-kansiossa oli `passtr`-hakemisto. Hakemiston sisällä oli muun muassa seuraavat tiedostot:

```text
Makefile
passtr
passtr2o
passtr.c
README.md
```

Luin aluksi README:n tiedoston, sen mukaan `passtr2o` oli valmiiksi käännetty binääri, jota tehtävässä piti tutkia debuggerilla.

Käynnistin ohjelman komennolla:

```bash
./passtr2o
```
Ohjelma käynnistyi ja kysyi:

```text
What's the password?
```

## GDB:n käynnistäminen

Käynnistin GNU Debuggerin komennolla:

```bash
gdb ./passtr2o
```

Ensimmäiseksi tarkistin ohjelman funktiot komennolla:

```gdb
info functions
```

GDB näytti muun muassa seuraavat funktiot:

```text
main
EaseEAs
check_password
mAsdf3a
```

Koska `check_password` vaikutti nimen perusteella salasanan tarkistamiseen liittyvältä, tutkin sitä ensin.

## check_password-funktion tutkiminen

Käytin komentoa:

```gdb
disassemble check_password
```

Tuloksena oli:

```asm
0x0000000000001257 <+0>:	xor    %eax,%eax
0x0000000000001259 <+2>:	ret
```

Funktio ei kuitenkaan tehnyt varsinaista salasanan tarkistusta, vaan palautti vain arvon 0. Tämän vuoksi tutkin seuraavaksi `main`-funktiota.

## main-funktion tutkiminen

Käytin komentoa:

```gdb
disassemble main
```

`main`-funktion assemblysta löytyi kohta, jossa ohjelma lukee käyttäjän syötteen:

```asm
call   0x1060 <__isoc99_scanf@plt>
```

Sen jälkeen kutsutaan funktiota:

```asm
call   0x125a <mAsdf3a>
```

Tämä vaikutti kiinnostavalta, koska `mAsdf3a` sai käyttäjän syötteen käsiteltäväkseen.

`main`-funktiossa oli myös kutsu:

```asm
call   0x1219 <EaseEAs>
```

Tämä funktio suoritetaan salasanan tarkistuksen jälkeen, joten se saattaisi liittyä FLAGin tulostamiseen.

## mAsdf3a-funktion tutkiminen

Seuraavaksi tutkin `mAsdf3a`-funktion:

```gdb
disassemble mAsdf3a
```

Funktiossa oli muun muassa seuraavat käskyt:

```asm
mov    %rdi,%rbp
mov    %rsi,%rbx
```

sekä:

```asm
movsbl 0x0(%rbp,%rax,1),%edx
movsbl (%rbx,%rax,1),%ecx
```

Tämän perusteella funktio käsittelee merkkijonoja merkki kerrallaan.

Kiinnostavin osa oli:

```asm
test   $0x1,%al
je     0x1299
sub    $0x7,%edx
jmp    0x129c
add    $0x3,%edx
cmp    %ecx,%edx
jne    0x12ac
```

Tästä pystyin päättelemään, että funktio muuttaa vertailtavan merkkijonon merkkejä indeksin perusteella ja vertaa tulosta käyttäjän antamaan salasanaan.

## Funktioparametrien selvittäminen

Asetin breakpointin `mAsdf3a`-funktioon:

```gdb
break mAsdf3a
```

Käynnistin ohjelman:

```gdb
run
```

Ohjelma kysyi salasanaa, joten annoin testiksi:

```text
hello
```

GDB pysähtyi `mAsdf3a`-funktion alkuun.

Tutkin rekistereitä komennolla:

```gdb
info registers rdi rsi rax
```

Tämän jälkeen tutkin, mitä merkkijonoja rekisterit osoittivat:

```gdb
x/s $rdi
```

Tulokseksi sain:

```text
0x7fffffffdce1: "anLTj4u8"
```

Seuraavaksi:

```gdb
x/s $rsi
```

Tulokseksi sain:

```text
0x7fffffffdcfc: "hello"
```

Tästä selvisi, että:

```text
rdi = "anLTj4u8"
rsi = käyttäjän antama salasana
```

Eli ohjelma vertasi käyttäjän syötettä merkkijonoon `anLTj4u8` tehdyn muunnoksen perusteella.

## Salasanan selvittäminen

Assemblysta selvisi, että ohjelma käsittelee merkkijonon merkkejä yksi kerrallaan.

Parillisilla indekseillä merkkiin lisätään 3:

```text
+3
```

Parittomilla indekseillä merkistä vähennetään 7:

```text
-7
```

Merkkijono oli:

```text
anLTj4u8
```

Kun muunnos tehdään:

```text
a + 3 = d
n - 7 = g
L + 3 = O
T - 7 = M
j + 3 = m
4 - 7 = -
u + 3 = x
8 - 7 = 1
```

Saadaan salasana:

```text
dgOMm-x1
```

## Salasanan testaaminen

Testasin löytynyttä salasanaa käynnistämällä ohjelman uudelleen:

```gdb
run
```

Kun ohjelma kysyi:

```text
What's the password?
```

annoin:

```text
dgOMm-x1
```

Asetin ohjelman pysähtymään `mAsdf3a`-funktioon ja tarkistin palautusarvon komennolla:

```gdb
info registers rax
```

GDB näytti:

```text
rax            0x1                 1
```

Tämä tarkoitti, että salasanan tarkistus onnistui, koska `mAsdf3a` palautti arvon `1`.

## FLAGin löytäminen

Jatkoin ohjelman suorittamista komennolla:

```gdb
continue
```

Tällä kertaa ohjelma hyväksyi salasanan ja tulosti:

```text
Yes! That's the password. FLAG{Lari-rsvRDx04WMBZpuwg4qfYwzdcvVa0oym}
```

Näin sain selville tehtävän vaatiman FLAGin.

## Lopputulos

Ohjelman oikea salasana oli:

```text
dgOMm-x1
```

Ohjelman tulostama FLAG oli:

```text
FLAG{Lari-rsvRDx04WMBZpuwg4qfYwzdcvVa0oym}
```

## Mitä uutta opin GNU Debuggerista

Opin Lab2-tehtävässä erityisesti seuraavia asioita:

* `info functions` -komennolla voidaan nähdä ohjelman funktioita.
* `disassemble`-komennolla voidaan tutkia funktion assembly-koodia.
* `continue` jatkaa ohjelman suorittamista seuraavaan breakpointiin tai ohjelman loppuun.
* `info registers` -komennolla voidaan tarkastella CPU-rekisterien arvoja.
* `x/s`-komennolla voidaan tarkastella muistiosoitteessa olevaa merkkijonoa.
* Funktioiden parametreja voidaan tutkia rekisterien avulla.
* Assembly-koodista voidaan päätellä, miten ohjelma käsittelee ja vertaa tietoa.
* Ohjelman salasanaa ei aina tarvitse arvata, vaan sen tarkistuslogiikkaa voidaan analysoida debuggerilla.


# Lab3

## 1. Ohjelman avaaminen GDBä

Aloitin avaamalla `crackme02e.64`-ohjelman gdb:llä:

```bash
gdb ./crackme02e.64
```

## 2. `main`-funktion tutkiminen

Katsoin ensin ohjelman funktiot:

```gdb
info functions
```

Sen jälkeen tutkin `main`-funktion assembly-koodia:

```gdb
disassemble main
```

Assemblystä löytyi muun muassa seuraavat kohdat:

```asm

0x0000000000001156 <+13>: mov $0x79,%eax 
0x000000000000115b <+18>: mov $0x0,%ecx 
0x0000000000001160 <+23>: lea 0xed0(%rip),%rdi # 0x2037 
0x0000000000001167 <+30>: movzbl (%rsi,%rcx,1),%edx 
0x000000000000116b <+34>: test %dl,%dl 
0x000000000000116d <+36>: je 0x1188 <main+63> 
0x000000000000116f <+38>: movsbl %al,%eax 
0x0000000000001172 <+41>: sub $0x2,%eax 
0x0000000000001175 <+44>: movsbl %dl,%edx 
0x0000000000001178 <+47>: cmp %edx,%eax 
0x000000000000117a <+49>: jne 0x11b6 <main+109>


```
lea eli Load Effective Address laskee muistiosoitteen ja tallentaa sen %rdi-rekisteriin. Tässä kohtaa %rdi saa osoitteen ohjelman käyttämään merkkijonoon.

Valitsin tämän kohdan tutkittavaksi, koska assemblyssä näkyi, että %rdi-rekisteriin ladataan muistiosoite juuri ennen kuin ohjelma alkaa käsitellä merkkejä. Halusin selvittää, mitä tässä muistiossa on.


## 3. Breakpoint `lea`-käskyn kohdalle

`disassemble main` -tulosteessa ensimmäinen `lea` oli kohdassa:

```asm
0x0000000000001160 <+23>: lea 0xed0(%rip),%rdi
```

Tämän perusteella asetin breakpointin:

```gdb
break *main+23
```


## 4. Ohjelman käynnistäminen argumentin kanssa

Ohjelma vaatii yhden argumentin, joten pelkkä:

```gdb
run
```

ei toiminut.

Käynnistin ohjelman esimerkiksi näin:

```gdb
run test
```

`test` oli tässä vaiheessa vain väliaikainen argumentti. Tarkoituksena oli päästä ohjelmassa eteenpäin ja tutkia sen toimintaa.

## 5. Merkkijonon selvittäminen

Breakpoint pysäytti ohjelman `lea`-käskyn kohdalle.

Suoritin ensin kyseisen käskyn:

```gdb
nexti
```

Tämän jälkeen `lea` oli ladannut osoitteen `%rdi`-rekisteriin.

Katsoin `%rdi` osoittaman merkkijonon:

```gdb
x/s $rdi
```

GDB näytti:

```text
"yuvmnpoi"
```

## 6. Merkkien muuntamisen selvittäminen

`lea`-käskyn avulla selvitin ohjelman käyttämän merkkijonon. Kun suoritin `lea`-käskyn ja tarkistin `%rdi`-rekisterin sisällön komennolla:

```gdb
x/s $rdi
```

GDB näytti:

```text
"yuvmnpoi"
```

Tätä voidaan ajatella ohjelman käyttämänä merkkijonona, josta ohjelma ottaa merkkejä yksi kerrallaan.

Tämän jälkeen katsoin uudelleen `disassemble main` -tulostetta ja tarkistin, mitä ohjelma tekee ladatulle merkille. Merkin käsittelyn kohdalla oli:

```asm
sub $0x2,%eax
```

`sub` tarkoittaa vähentämistä, joten tässä ohjelma vähentää merkin ASCII-arvosta 2.

Esimerkiksi ensimmäinen merkki on `y`, kun siitä vähennetään 2:

```text
y → x → w
```

eli tulokseksi saadaan `w`.

Sama tehdään merkkijonon jokaiselle merkille:

Näin merkkijonosta:

```text
yuvmnpoi
```

saadaan:

```text
wstklnmg
```

Tätä arvoa käytin ohjelman salasanana.


## 7. Koko salasanan tarkistaminen GDB:llä

Halusin vielä tarkistaa GDB:n avulla, että koko päätelty salasana oli oikein.

Assemblyssä merkkien vertailu tapahtuu kohdassa:

```asm
cmp %edx,%eax
```

Asetin breakpointin tähän kohtaan:

```gdb
break *main+49
```

Käynnistin ohjelman saadulla salasanalla:

```gdb
run wstklnmg
```

Breakpoint pysäyttää ohjelman jokaisen merkin vertailun kohdalla. Tarkistin rekisterien arvot komennolla:

```gdb
info registers eax edx ecx
```

`%eax` sisältää ohjelman laskeman odotetun merkin ja `%edx` sisältää käyttäjän antaman salasanan nykyisen merkin. `%ecx` kertoo, monennetta merkkiä käsitellään.

Jatkoin ohjelman suorittamista seuraavaan vertailuun komennolla:

```gdb
continue
```

ja tarkistin rekisterit uudelleen:

```gdb
info registers eax edx ecx
```

Toistin tämän jokaiselle merkille.

Kaikissa vertailuissa `%eax` ja `%edx` sisälsivät saman merkin. Näin koko salasana

```text
wstklnmg
```

vastasi ohjelman odottamaa arvoa.

Tämän perusteella varmistin, että päätelty salasana oli kokonaisuudessaan oikein.


## 8. Ratkaisun testaaminen

Poistuin GDBä:

```gdb
quit
```

Testasin ohjelmaa normaalisti terminaalissa:

```bash
./crackme02e.64 wstklnmg
```

Tarkistin ohjelman paluuarvon:

```bash
echo $?
```

Tulokseksi tuli:

```text
0
```

Paluuarvo `0` tarkoittaa, että ratkaisu oli oikein.

## Lopputulos

Ohjelman oikea salasana on:

```text
wstklnmg
```

Ohjelma palautti salasanalla paluuarvon `0`, joten crackme oli ratkaistu.
